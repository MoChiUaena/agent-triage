# 历史记录管理

从侧栏“全部记录与筛选”打开工作区管理页。侧栏保留最近 20 条的快捷入口，完整历史页面每页 20 条，可继续翻页查看更早的记录。

可以按问题关键词、服务、状态、判断模式和日期筛选。服务列表来自已保存的执行，因此从启动配置移除的服务仍可查询历史。日期按浏览器时区解释，包含所选起止日；服务名称使用执行时保存的名称。

分页采用创建时间与 ID 游标。新增记录不会把后续页中的旧记录向后挤；点击刷新回到第一页。游标不能复用于不同筛选条件。数据库时间精度可能与 JSON 时间不同，游标使用数据库中的实际时间。

点击“查看”直接打开这条记录的概览、证据与执行事件，不重新调用模型。保存该链接后仍可重新打开，已删除记录返回不存在。

## 删除

只有完成、证据不足、失败和取消的记录可删除。排队和运行中的记录会在页面禁用删除，后端也会拒绝请求。

点击删除后，确认窗口显示原问题、服务、创建时间和状态；“保留记录”关闭窗口，确认删除后才提交请求。删除包括本条记录保存的结果、证据与事件，无法通过页面恢复。模型设置保存在另一张表中。

浏览器请求需要本机同源访问和 `X-Triage-History: 1`；确认体中的 UUID 必须与路径一致，防止确认对象与删除对象错位。没有自动清理任务。

## 旧数据与接口

V3 数据库迁移增加查询索引列。启动时分批从旧 JSON 补齐服务、模式、问题、耗时和用量索引，不重写原始 JSON；新执行每次保存时原子更新 JSON 与索引。

`GET /api/history` 返回 `items`、`total`、`nextCursor` 和 `pageSize`，窗口最多 50 条。关键词按字面搜索，`%` 与 `_` 不作为通配符。时间参数 `from` 包含、`until` 不包含，均为 ISO-8601 时间。

`GET /api/history/services` 返回已记录的服务标识与最新名称。`DELETE /api/history/{id}` 需要 JSON 确认体 `{"confirmId":"同一个 UUID"}`，成功返回 204；不存在为 404，执行未结束为 409。原有 `GET /api/runs?limit=20` 数组接口保持可用。

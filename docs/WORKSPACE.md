# 工作区管理

从侧栏“历史与统计”进入工作区管理页。排查记录每页 20 条，可筛选、翻页并打开保存的结果；运行统计与服务状态在同页标签中切换。侧栏在四个页面保持相同的固定导航。

可以按关键词、服务、接口、状态、判断模式和日期筛选。关键词也支持接口路径和处理方法。服务与接口选项来自已保存的执行，因此移除服务或修改接口后仍可查找旧记录。日期按浏览器时区解释，包含所选起止日；每条记录展示执行当时的服务名称和接口描述。

“排查范围”默认包含所有记录。选择服务后可以指定接口，也可以选“整个服务”，只查看未限定接口的排查；旧记录归入这一类。同一路径的处理方法变更后会保留不同选项，选项附有方法签名。筛选操作只读历史，不访问业务服务或调用模型。

分页采用创建时间与 ID 游标。新增记录不会把后续页中的旧记录向后挤；点击刷新回到第一页。游标不能复用于不同筛选条件。数据库时间精度可能与 JSON 时间不同，游标使用数据库中的实际时间。

点击“查看”直接打开这条记录的概览、证据与执行事件，不重新调用模型。保存该链接后仍可重新打开，已删除记录返回不存在。

## 删除

只有完成、证据不足、失败和取消的记录可删除。排队和运行中的记录会在页面禁用删除，后端也会拒绝请求。

点击删除后，确认窗口显示原问题、服务、接口范围、创建时间和状态；“保留记录”关闭窗口，确认删除后才提交请求。删除包括本条记录保存的结果、证据与事件，无法通过页面恢复。模型设置保存在另一张表中。

浏览器请求需要本机同源访问和 `X-Triage-History: 1`；确认体中的 UUID 必须与路径一致，防止确认对象与删除对象错位。没有自动清理任务。

历史页还可手动选择保留最近 30、90、180、365 或 730 天。预览只返回截止时间与符合条件的终态记录数；确认窗口要求输入“删除旧记录”，服务端再次核对数量后才删除。若预览后记录数变化，返回 409 并要求重新预览。排队和执行中的记录、模型设置及最近 30 天的记录不会被这项清理操作删除。清理不可恢复，操作前应备份本机数据库。

## 旧数据与接口

V3 数据库迁移增加查询索引列，V6 补充接口索引与回填版本。启动时分批从保存的 JSON 补齐查询列，不重写原始 JSON；没有接口的记录同样标记为已回填。新执行每次保存时原子更新 JSON 与索引。

`GET /api/history` 返回 `items`、`total`、`nextCursor` 和 `pageSize`，窗口最多 50 条。关键词按字面搜索，`%` 与 `_` 不作为通配符。时间参数 `from` 包含、`until` 不包含，均为 ISO-8601 时间。

`GET /api/history/services` 返回已记录的服务标识与最新名称。`DELETE /api/history/{id}` 需要 JSON 确认体 `{"confirmId":"同一个 UUID"}`，成功返回 204；不存在为 404，执行未结束为 409。原有 `GET /api/runs?limit=20` 数组接口保持可用。

`GET /api/history/retention?days=90` 预览 30–3650 天的终态旧记录。`POST /api/history/retention` 需要 `X-Triage-History: 1` 和预览返回的 `cutoff`、`eligibleCount`（作为 `expectedCount`）及确认文字 `删除旧记录`；数量变化返回 409。没有后台定时删除。

`GET /api/history/endpoints?service=ticket-service` 返回该服务已保存的接口描述，最多 200 个，按路径、HTTP 方法和接口 ID 排序。历史条目与最近摘要的 `endpoint` 均来自执行快照，旧记录为空。

`GET /api/history?service=ticket-service&endpointId=EP-...` 查询具体接口；此时必须指定服务。`endpointId=SERVICE` 只查整个服务范围的记录，也可用于全部服务。省略 `endpointId` 包含两类记录。接口筛选参与游标校验，更换范围后需从第一页查询。

## 运行统计

“运行统计”按近 7、30 或 90 天查看，可按历史服务和接口筛选。页面显示本次查询采用的范围，记录按创建时间归入时段，显示当前执行状态分布、工具调用次数与模型调用轮次。

耗时是提交到终态的时间，包含排队；平均、p95 与最大值只使用保存了有效终态时间的记录。p95 采用离散分位数，没有样本时显示为空。

输入、输出与总 Token 汇总已返回的已知用量，兼容旧记录的完整 `usage`。完整、部分已知和未返回用量分别计数；没有任何已知用量时显示“—”。这些是执行与用量统计，不作为故障判断准确率或账单金额。

`GET /api/statistics?days=7&service=order-service` 返回状态、耗时、调用与用量覆盖，`days` 范围 1–90。`endpointId` 与历史筛选规则相同，响应回显 `service` 与 `endpointId`。统计读取同一数据库快照，删除记录后重新查询会更新汇总。

## 服务状态

“服务状态”显示启动配置登记的服务、观测协议、允许窗口、检查窗口、请求数、耗时和检查时间。接口可读取与窗口有无请求分别显示；默认合成数据不会显示为实际服务连通。

检查只读取服务观测，不生成业务请求，不依赖模型选择。连接失败、版本不匹配或字段契约错误使用应用固定的提示，接口不公开服务地址或凭据。

`GET /api/services/status` 使用有界并发检查，结果缓存五秒。刷新时查看卡片的检查时间；未完成或暂时繁忙会返回明确状态，已有页面仍可继续使用。

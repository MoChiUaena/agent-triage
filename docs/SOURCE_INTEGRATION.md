# 接入本机 Java 源码

打开“项目源码”页面，填写项目名称、本机目录，并绑定一个已登记的服务。返回排查页，勾选“本次检索源码”后，结果中的“代码引用”会显示候选文件、方法、接口路径和代码片段。独立工单项目的复现方式见下方。

服务观测接入和源码登记是两件事。只登记源码不会产生运行指标；实际服务仍需通过 [Starter](STARTER.md) 或[只读观测接口](SERVICE_INTEGRATION.md)接入。源码可以辅助定位需要检查的代码，不能证明某个方法执行过，也不能据此确认运行根因。

项目卡片可以修改名称、目录和服务绑定。修改目录会先索引新目录，成功后再替换原登记；读取失败时保留原项目。解除绑定后仍可本机检索，也可以再次绑定服务。修改、解绑和重新索引会更新项目版本并关闭旧模型授权。删除索引需要确认项目与版本，只删除登记和索引，源文件与历史排查片段仍保留。

## 索引范围

索引使用 JDK 21 的语法解析接口，不编译项目、不加载项目类、不执行注解处理器。依赖缺失不会阻止语法解析；语法错误文件会跳过。提取类、方法、声明类型、调用位置和 Spring MVC 注解中的首个静态路径。根据源码声明做有限的静态匹配，不做编译器完整类型分析或跨服务追踪。

只读取 UTF-8 的 `.java` 文件。跳过 `.git`、`.idea`、`.gradle`、`target`、`build`、`data`、`logs`、`node_modules`、`dist` 和 `.env` 目录，以及链接文件和链接目录。疑似含常见硬编码凭据的 Java 文件会整体跳过；该检查不能覆盖所有敏感内容。

每个服务绑定一个项目，最多登记 20 个。单项目最多 2000 个 Java 文件、20 MB、10000 个符号，索引时限 30 秒；单文件不超过 256 KB、1000 个符号，每个方法最多索引 30 条调用。较大仓库可以登记一个模块目录。

本地数据库保存路径、符号、行号和文件 SHA-256，不保存完整源码。检索按问题、错误事件和对应观测的调用关键词返回最多 5 个候选。片段最多 80 行、3600 字符；读取时核对文件摘要，代码变化后需要重新索引。历史排查会保存当时展示的片段，便于复查。

## 查看调用关系

检索结果中点击“查看调用关系”，或在排查结果的“代码引用”中查看本机静态调用关系。可以从 Controller 跟到 Service、Gateway 和常见 HTTP／JDBC 调用位置，点击查看调用行或目标方法。

字段、参数和已声明的局部变量提供接收对象类型；明确参数可辅助匹配重载。接口唯一已索引实现显示为候选，多个实现或无法确定的重载并列展示。局部变量遮蔽字段时按局部声明处理。回调、Lambda、方法引用、未知返回类型、索引外依赖和反射不作为确定的执行步骤展开。

最多展开 3 个入口、4 层、12 个方法和 32 条调用。循环调用不会反复展开，达到限额会提示部分调用未展示。片段仍按文件摘要验证，调用行超出方法前 80 行时会另取调用行附近的片段。旧索引需要手动重新索引后才有调用信息，旧历史片段仍可读取。

运行证据按观测类型关联到 HTTP 请求、获取连接或 SQL 操作的位置。引用指向本次已收集的指标与日志；窗口超时可以提示优先核查某类调用，不能证明该方法执行过，也不能确认具体请求路径或根因。无请求窗口、只有 SQL 错误等情况分别提示，不混同为连接池耗尽。

开启[接口观测](STARTER.md)后，V3 优先按实际匹配的处理方法类名、方法名和参数类型寻找入口，无需在问题中填写类名或接口路径。页面可以分别排查正常接口和超时接口。源码与运行方法签名不兼容、没有对应文件或存在多个候选时会说明原因；匹配也不能替代运行版本校对或完整调用轨迹。

调用关系和新增展开片段只在本机展示，不扩大模型请求的片段范围。历史记录保存当时的调用关系，后续修改目录、解绑或删除索引不会改写它。

## 错误位置与源码

Starter 的 HTTP V3 可[按业务包采集错误位置](STARTER.md#采集错误位置)，默认关闭。勾选“本次检索源码”后，“代码引用”会先展示错误位置、对应日志引用与源码匹配状态，点击“查看”打开附近代码，并突出显示观测行。

HTTP 调用失败记录当时业务线程的位置；请求异常穿过过滤器时读取异常栈。事件保留时间、请求标识、异常类型和有界业务位置，不包含异常正文。位置可用于核查正在执行的调用，不能据此确认最初抛错处或运行根因，也不等于跨线程、跨服务的完整轨迹。

匹配使用类名、方法名、Java 文件名和行号。行号可以区分重载；没有行号时显示方法候选，同名模块或其他歧义最多展示两个候选。索引外位置、文件名不符、行号超出方法范围和文件修改分别说明，不按相近名称强行绑定。读取附近片段仍验证索引摘要，匹配本身不证明源码与运行构建同版。

每次最多展示三条错误事件，每条最多八个业务位置。旧服务和未开启采集的服务仍可使用原有源码检索与静态调用关系。历史保存当时的位置和片段，重新索引不会改写旧排查。

这些位置和额外展开的片段仅在本机展示，不进入运行模型或可选源码模型消息；原候选选择流程和授权范围保持原样。

## 模型读取

默认只在本机检索。模型读取需要同时满足：

1. 在模型设置页启用已保存的模型服务。
2. 在项目源码页确认接收服务、模型、配置版本和片段范围。
3. 在本次排查中勾选“本次允许模型查看候选代码”。

项目授权绑定模型服务 ID、配置版本和源码索引版本。切换模型或更新配置后，旧授权不适用；重新索引会关闭授权。提交任务后再次检查授权和文件摘要，未经允许的代码不会进入运行诊断的模型消息。

运行判断完成且窗口有请求观测时，剩余轮次与时长允许才另发起一次候选选择请求，包含最多 5 个验证过的片段、问题和相关观测。模型只能选择其中最多 3 个引用 ID，不能请求额外路径、执行项目或生成自由归因。无效引用、超时或轮次不足会保留运行判断和本机候选。关闭授权无法收回已经发出的请求。

源码管理、排查记录和 SSE 结果只允许本机同源访问，不提供远程代码上传或仓库克隆。`data/`、`target/`、日志与本地密钥不应提交到版本库。

## 独立验证

`verification/ticket-service` 是单独的 Spring Boot 工单应用，通过 Starter 记录同步 HTTP 调用。验证脚本启动自己的工单 JVM、分配接口和 Agent JVM，复制一份源码到忽略的 `target/source-smoke/`，不依赖已经运行的订单、商品或数据库样例。

```powershell
.\mvnw.cmd verify
.\mvnw.cmd -f integrations/pom.xml verify
python scripts/source_integration_smoke.py
python scripts/source_integration_smoke.py --protocol-v3
```

脚本检查正常请求、两次实际 HTTP 超时、Controller → 接口实现候选 → Gateway → HTTP 调用、片段与调用行号、证据关联、多个实现的歧义、修改文件后的拒绝、项目管理和历史快照。该脚本不请求付费模型。`SourceIntegrationTest` 另用本地协议服务检查双重授权、旧授权失效、无效引用、轮次限额、超时，以及调用关系展开不扩大模型输入；这些验证说明接口行为，不代表真实模型的代码定位准确率。

V3 验证使用两个真实接口和同名重载处理方法，检查通用问题也能关联入口、不同接口统计不会混用，以及旧 V1 接入仍然可用。`EndpointRunApiTest` 用本地模型协议服务检查默认请求不带接口模板或处理方法描述。

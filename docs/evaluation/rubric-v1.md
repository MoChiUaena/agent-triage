# 人工评审标准 v1

用于同一问题、同一批本地订单请求的“仅文档”和 Agent 对照。每例先核对样例服务的请求数、超时率与错误事件，再读两份回答。模型和案例由运行记录注明；这里不把小样本结果称为诊断准确率。

1. **当前状态**：仅文档回答不得声称看到了当前 p95、超时率或 traceId；可以解释通用规则并说明缺什么。Agent 提到的当前数值、错误类型和时间窗口必须与本次工具证据一致。
2. **归因边界**：p95 接近不能证明订单耗时全部来自库存；请求超时不能证明库存服务不可用，也不能写成单独的读取超时。没有 CPU、网络、连接池、数据库观测时，不得断言库存内部根因。正常窗口只能说“未发现库存调用超时”，不能保证服务整体正常。
3. **引用与范围**：引用 ID 必须来自本次结果；成功结论要用与当前正常或超时状态相符的规则。无关问题应拒绝。`SCOPE_GATE`、`EVIDENCE_GATE` 是应用决定，单独记录，不计作模型自主判断。
4. **不确定性**：回答应说明本地样例请求少、观测有限；不能把结果推广到生产环境。失败状态保留失败码，不按成功评价。

人工标记为 `可用`、`需修订`、`失败` 或 `应用门槛`，并摘录具体原因。结构检查只负责状态、引用 ID 与调用记录；通过结构检查不自动得到“可用”。本标准在首次运行留出集前固定；若看过留出结果后再改标准或实现，须另建留出集才可做独立复测。

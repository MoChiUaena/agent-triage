# 评审标准 v3：参数纠正与检查建议

沿用 v2 的窗口事实、匹配规则、归因范围和结论来源要求。v2 留出集已经使用；P01/P02 仅作调试回归，R01–R08 首次运行前固定本标准与实现。

- 工具参数错误要有 `TOOL_ARGUMENTS_REJECTED`，只记录应用生成的 SIZE、JSON、FIELDS、SERVICE、WINDOW 或 QUERY 分类与固定消息，不回显模型参数。整批工具先校验再执行；未注册工具或重复调用 ID 直接失败。
- 每次排查最多允许一次参数纠正，纠正使用原有模型轮次、工具次数和总时限。再次无效必须停止；不能通过替换服务、窗口或放宽校验来完成任务。
- 真实模型未产生无效参数时，不能据此声称它测试了纠正路径。该路径由注入无效参数的本地接口模拟器验证，明确标记 `mockProvider=true`。
- 成功结论必须引用当前指标、日志与匹配规则，判断与请求数和窗口超时率一致。已有这些证据时，不再选择 COLLECT_OBSERVATIONS 或 SEARCH_MATCHING_RULE；没有日志 traceId 时不得选择 CORRELATE_TRACE。
- 检查项代码保存于 `modelExecution.nextChecks`，文字由应用生成。除了满足允许列表，还要人工检查建议是否针对当前问题；“不重复查询”不能直接等同于“建议最优”。
- 空窗口、无关问题和规则缺口继续区分应用门槛与模型判断。记录失败、完整 usage 与实际轮次，不重跑留出失败来替换首次结果。

逐例仍标记“满足契约”“应用门槛”或“失败”，并另列建议质量与参数拒绝次数。本组评价系统执行边界与输出契约，不评价模型自由归因能力，不统计生产诊断准确率。

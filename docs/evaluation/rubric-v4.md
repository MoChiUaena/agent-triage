# 评审标准 v4：规则完整性与应用排序

沿用前版的窗口事实、有效引用与归因边界要求。v1–v3 留出集已使用；Q01/Q02 只作回归，T01–T06 首次运行前固定实现和本标准。

- LIVE 文档检索提供订单服务的正常与超时基础参考，同时保留关键词命中的证据说明。`queryMatched` 与 `serviceReference` 必须区分召回来源。基础规则不证明现场状态；两种对照方法使用相同的检索改动，不能把召回增加说成模型能力提升。
- 模型提前输出时，只有缺少必需证据或引用可触发一次 `EVIDENCE_FEEDBACK`。缺少工具观测时必须留有查询及最终输出的轮次与工具额度；已有证据只更正引用。未知引用、格式错误或矛盾判断仍拒绝，不自动填充证据。
- 参数更正、证据反馈均占用原有模型轮次与总时限。第二次不完整或预算不足必须停止；不能靠增加限额完成案例。真实模型没有触发该路径时，只报告模拟接口的注入验证。
- 必需来源齐全时请求使用 `tool_choice=none` 进入最终输出，不继续查相同窗口。接口不遵守该请求时，执行网关仍保留工具次数与重复调用校验。
- `requestedNextChecks` 保存模型原始有效选项；应用按观测条件排序并展示最多两项，记录 `CHECKS_PRIORITIZED`。展示项必须来自原始选项，不加入未选择建议；没有 traceId 等不合格选项仍拒绝。聚焦与排序属于应用策略，不属于模型自主排序。
- 成功结果须有对应规则、指标与日志，数值与实际窗口一致。空窗口和无关问题区分应用门槛，不算模型自主判断。

逐例记为“满足契约”“应用门槛”或“失败”，保留用量、反馈次数、原始与展示检查项。建议是否有用仍需人工审阅，不以此估计生产准确率；不重跑留出失败来替换首次结果。

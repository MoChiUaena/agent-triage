# 观测容量与窗口边界验收

2026-10-01，主分支补齐容量淘汰后的窗口拒绝规则。[跨平台容量检查](https://github.com/MoChiUaena/agent-triage/actions/runs/36844572102)和[常规 CI](https://github.com/MoChiUaena/agent-triage/actions/runs/36844572081)均通过，检查代码为 `412c499f06507d9b52a26de66d1134ead2761c40`。主项目 272 项、Starter 48 项、订单样例 4 项、数据库样例 8 项测试无失败；Windows 的符号链接权限检查允许跳过，PostgreSQL 由单独作业验证。

订单和数据库演示适配器原来只移除最早的记录，随后仍返回 200。新增回归先复现了五项失败：请求容量溢出、丢失记录恰好位于包含起点的窗口边界，以及数据库池采样溢出。修复后，它们记录最晚的丢失时间，受影响窗口返回 422；严格晚于丢失边界的新窗口仍可读取。刚好填满请求容量时不会提前拒绝。实验重置继续清空本次实验数据，不用于验证跨重置的观测连续性。

Starter 的并发测试让八个写入线程与一个读取线程共享采集器，检查累计请求、接口合计、超时合计和响应分类的一致性。HTTP、按接口筛选、数据库记录和池采样均覆盖容量边界。另一项失败回归复现了保留期清理后的时钟回拨：已清理的超时样本被遗漏，旧窗口却能返回剩余正常请求。现在过期清理也保留丢失边界，回拨不会使缺少样本的窗口恢复为完整。

Windows 和 Linux 分别启动隔离的库存、HTTP/JDBC 商品应用及两个 Agent 进程。八个并发客户端把容量为 32 的 HTTP 和 JDBC 采集器填满，核对 V1、V2、V3 的计数；第 33 条记录后，服务窗口和已选接口都返回 422。固定规则与本地模型协议各运行两次排查，均以 `OBSERVATION_WINDOW_LOST` 结束，保留失败事件，没有诊断或 `RUN_COMPLETED`；模型模式仅完成一次本地协议调用。既有空窗口、正常、超时、恢复和引用检查同时通过。

这些检查验证计数和拒绝边界，不是吞吐基准或长时间资源测试。采集记录在进程重启后清空，也不证明重启前后的观测连续性。模型协议服务和凭据均为测试固定值，没有调用付费模型；进程日志、密钥和原始记录留在被忽略的 `target/` 中。已发布的 v0.10.0 标签和附件未改动。后续继续检查异步任务、取消操作和长期运行时的资源留存。

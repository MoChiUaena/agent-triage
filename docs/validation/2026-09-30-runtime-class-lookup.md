# 运行类查询开销与打包核对

2026-09-30，[Petclinic 验收](https://github.com/MoChiUaena/agent-triage/actions/runs/36675070996)在 Linux CI 进程里连续查询两个已加载业务类。预热 50 次后记录 200 次，不含 HTTP 往返和异常处理；测量的是 Java Agent 枚举已加载类、确认类名唯一的直接耗时。

| 样本 | p50 | p95 | 最大值 |
|---|---:|---:|---:|
| 200 次连续查询 | 1.262 ms | 1.309 ms | 1.462 ms |

这是一台 CI 机器上的一次短时结果，不能当作其他应用的延迟保证。若每秒持续查询数百次，枚举开销会随错误流量累积。因此 Starter 在单实例应用中每秒最多自动查询 20 次；超过上限的异常帧保留“未知”，不复用可能过期的类引用。直接基准入口不经过这道限频，用来观察查询本身的成本。生产接入仍应先在目标服务测量错误量与尾延迟。

打包回归使用提交 `a49d549`：新演示包包含独立 Agent JAR，四个附件均有 SHA-256，ZIP 内 25 个白名单条目，`verify_release.py` 全部通过。[原始 v0.4.0 发布附件](https://github.com/MoChiUaena/agent-triage/releases/tag/v0.4.0)没有 Agent JAR，同一校验器仍按旧格式核对三附件与 24 个条目。旧发布文件未修改，本次生成的本地包和基准原始 JSON 均留在忽略目录。

# 取消与异步资源留存验收

2026-10-01，[五分钟资源检查](https://github.com/MoChiUaena/agent-triage/actions/runs/36878213167)的四个作业通过。[最终常规 CI](https://github.com/MoChiUaena/agent-triage/actions/runs/36879390369)通过主项目 275 项、Starter 51 项、PostgreSQL、实际 HTTP 与本地模型协议检查，包括取消 API 的 4 项回归；Windows 符号链接权限检查允许跳过。修复和持续运行检查来自 `b03e820c667dd2ae9af3b8b0047f7482ccc60052`；最终常规检查对应增加 SSE 回归后的 `c5ab968d36019f028cb7f6bef48d0541df6cd341`，应用代码保持相同。

修复前，两项回归分别复现了关闭后留下六个排队任务的运行登记，以及保留已完成快照时业务类加载器不能回收。`shutdownNow()` 返回的未启动 Future 现在会收到取消通知，协调任务的完成回调可移除运行登记；持久化的未完成记录继续按原有重启规则恢复。响应完成时，上下文先冻结观测结果，再清除处理类、接口和故障位置引用。回归保留快照并实际检查类加载器的弱引用回收，原有 MVC 异常、迟到调用与窗口结果仍通过。

每个持续运行作业使用 JDK 21，堆为 `-Xms96m -Xmx256m`，运行 300 秒：

| Agent / Linux | 983 | 4915 | 12.06 | 13.43 | 12.84 |
| Agent / Windows | 926 | 4630 | 11.72 | 13.10 | 12.70 |
| Starter / Linux | 28279 | 28279 | 8.64 | 9.00 | 8.76 |

Agent 每轮交替阻塞工具或模型任务，取消四个运行中任务和一个排队任务，确认迟到结果不发布；再提交新任务，确认执行器继续工作。每轮运行登记、队列和借用连接均归零，单个执行器最多四个工作线程。内存 H2 中只删除本测试的终态记录，避免将正常历史留存误当成执行器泄漏。模型队列使用可控 Callable，HTTP 协议由常规 CI 另行检查。

Starter 每轮完成一个异步请求：工作线程执行正常 JDBC 和失败 SQL，取消等待任务，响应完成后再执行一次迟到查询。正常和失败操作分别产生观测，迟到查询不再归属已完成请求；四个工作线程逐一确认没有遗留上下文。HTTP/JDBC 样本各最多 512 条，池采样有界，借用连接归零；关闭观测器后采样线程终止，应用拥有的连接池仍可用。另有二十次 JDBC 观测器创建和关闭的回归。

新增 SSE 检查连续回放八十次已取消任务的事件流，确认完整结束、连接名额回到初始值、定时查询队列为空。这项检查覆盖终态回放，不等同于长连接提前断开的持续运行验收。

堆数据在请求 GC 后采样，检查允许相对预热基线上浮 64 MiB；表中记录实际值，轮次不是吞吐基准。五分钟没有覆盖数天运行、原生内存、真实供应商的网络取消或任意数据库驱动。忽略中断的外部调用仍可能占用固定线程，取消也不证明供应商停止计费。测试未调用付费模型，也未使用本机数据目录、凭据或日志；v0.10.0 标签和附件保持原样。下一项整理真实应用的接入成本与运行限制。

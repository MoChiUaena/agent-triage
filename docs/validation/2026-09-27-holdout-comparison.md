# 10 个留出案例的首次对照

评审前已提交[标准 v1](../evaluation/rubric-v1.md)，留出集首次运行时没有改提示词或规则。使用百炼 `qwen3.7-flash-2026-07-15`、LIVE 数据源；每例重新生成 5 次本地订单请求，让同一个模型分别回答“仅文档”和“Agent 可调用工具”。评测导出的原始 JSON 保存在被 Git 忽略的 `target/live-comparison/`，Agent 执行历史另存于本机被忽略的 `data/`；本报告不包含 API Key、提供商本地配置 ID 或 traceId 明文。

| 案例 | 仅文档 | Agent | 人工检查 |
|---|---|---|---|
| H01 下游超时 | 证据不足 | 成功，3 工具 / 2 轮 | 需修订：把请求总超时称为“读取超时” |
| H02 下游超时（英文） | 证据不足 | 成功，3 工具 / 3 轮 | 可用：窗口数字、超时日志与不确定性相符，未断言库存内部根因 |
| H03 询问库存超时影响 | 通用指导 | 成功，3 工具 / 2 轮 | 两边需修订：仅文档沿用“读取超时”措辞；Agent 又推断“库存不可用”、把相近 p95 说成主要耗时归因 |
| H04 正常对照 | 证据不足 | `INVALID_MODEL_OUTPUT`，3 工具 / 2 轮 | Agent 失败；三类证据已取得，但最终格式或引用未通过服务端校验 |

| H06 正常延迟 | 证据不足 | `INVALID_MODEL_OUTPUT`，3 工具 / 2 轮 | Agent 失败；未保存不合格结论，原始模型回复未留存 |

| H09 实际超时 | 证据不足 | 成功，3 工具 / 2 轮 | 需修订：正文把日志里的一个 traceId 抄错一字符，还写了证据未证明的“库存不可用” |

仅文档方法没有把规则冒充现场观测，却不能直接回答当前是否超时。Agent 有 5 条成功结论、2 条被格式/引用校验拒绝、3 条由应用门槛结束；5 条成功中，按固定标准只有 H02 可直接使用。成功结果的引用 ID 均有效，但 H09 正文仍写错了一个日志 traceId，证明“引用存在”不能保证句子逐字得到支持。

本次留出集中服务端返回的 usage：仅文档共 18543 token，Agent 共 42766 token；这只统计该次运行的记录，不等于服务商账单，也不包含此前调试与连接测试。相同问题下 Agent 通常使用更多 token，换来了当前窗口证据，但自由文本归因仍是主要风险。

本组留出集已经使用。今后若根据 H09 等发现修改实现，应另建新留出集验证新版本，不再把这十例当作独立效果证明。这里没有生产流量，也没有据此计算一般故障诊断准确率。

报告完成后，代码增加了对正文 traceId 的本次日志匹配检查，并用精确匹配与 H09 类似的误写做了单元测试。此改动尚未用新的独立留出集评测，因此上表仍是修订前版本的结果。

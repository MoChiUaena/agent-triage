# 请求执行阶段判断验收

2026-10-02，入站 V4 增加默认关闭的 `request-failure-counts`。窗口和接口分别记录执行异常、仅返回 5xx、异步超时、异步错误与已处理异常；错误事件增加固定码和响应类。原有未采集分类的窗口、旧协议和历史继续读取。[配置与门槛](../REQUEST_EXECUTION.md)说明具体要求。

[最终常规 CI](https://github.com/MoChiUaena/agent-triage/actions/runs/36989333304)通过 Windows/Linux 的主项目 289 项、Starter 62 项，以及 PostgreSQL、实际样例、本地模型协议和 DOM 渲染检查，提交为 `f358c43e1cd331d6115192ac64e6c1d8f1538160`。[容量](https://github.com/MoChiUaena/agent-triage/actions/runs/36989260822)和[五分钟资源回归](https://github.com/MoChiUaena/agent-triage/actions/runs/36989260778)也通过，对应此前 `ad495071ff18efea4eb87b2a453c8ed13b083920`；后续只增加公开项目验收步骤。CI 两平台没有跳过；本机 Windows 的符号链接权限检查跳过一项。

采集回归使用实际过滤器与 MVC 处理流程，区分抛出的执行异常和直接返回的 503。在不开启堆栈采集时，已转为 404 的异常仍单独记为已处理异常；异步超时或错误不记成执行失败，完成后的迟到信号忽略。不开启新开关时没有新增分类字段。非法模式或缺少响应分类在启动时拒绝。

读取回归拒绝缺少分类项、负数、小数、接口和窗口分类不一致、数据库码混入请求分类、响应类冲突，以及超过对应计数的错误事件。执行判断要求同服务、同起止时间、同请求及分类计数，存在本窗口 REQUEST_EXECUTION_FAILED 事件与对应规则。缺少规则、错误码不符或计数矛盾保持证据不足。

固定规则与本地模型协议对同一分类执行异常都返回成功的阶段判断，并引用指标、日志和规则；历史回读保留分类。只有 5xx 响应时，两种模式都保持证据不足，模型不再请求最终成功判断。旧下游与数据库模式的原有判断契约也通过回归。模型只选择固定类型、引用与检查项，应用生成“本窗口请求执行阶段发生异常”的措辞，不推断内部根因。

[固定 Petclinic](https://github.com/MoChiUaena/agent-triage/actions/runs/36989406729)完成六组检查：旧 V3、旧 V3 加 JPA、未开启分类的 V4、V4 加 JPA、开启分类的 V4，以及分类与 JPA 同时开启。原有正常页保持证据不足；主人详情中两次原有异常配合两个未知响应、两个执行异常事件及规则，支持执行阶段判断。SQL 执行和连接获取阶段继续独立，源码摘要差异与冻结历史检查通过。所有本次应用进程停止。

[Petclinic REST](https://github.com/MoChiUaena/agent-triage/actions/runs/36989411253)保持旧 V3 验收原接口、响应分类、同步和异步下游超时、显式包装、并发与迟到调用、源码版本。它证明旧能力兼容，不替代新分类在 REST 项目中的完整混合故障对照；这项仍按路线图推进。

本轮没有调用付费模型，不读取本机设置、历史或原始业务日志，运行数据和公开项目副本留在忽略目录。v0.10.0 标签和附件未修改。新判断只确认已采集的请求异常阶段，具体 404 条件、网络、下游、数据库内部根因、更多客户端及数天稳定性仍未覆盖。

# v2 调试集：证据约束输出

使用百炼 `qwen3.7-flash-2026-07-15`，温度 0，最多 4 轮，输出上限 1600 token，单次模型时限 45 秒。订单与库存服务在独立 JVM 中处理实际 HTTP 请求，Agent 使用 LIVE 数据源。每例按 [v2 案例](../evaluation/cases-v2.json)重新生成请求，再分别运行仅文档问答和 Agent。

首批 C01–C04 中，C01、C02、C03 都已取得三类证据，但最终选择未通过校验；C04 由无请求门槛结束。当时错误消息没有细分原因，不能断言三次失败原因完全相同。增加脱敏错误分类后，单独复查 C01，确认模型漏选了匹配的规则引用。随后补全输出格式的字段与数组限制，并在工具返回后按来源列出可选 ID；服务端的证据校验没有放宽。

下表为修订后重新运行的全部 6 个调试案例。它属于调试结果，不是独立留出效果。代码版本为 `f5ec567`；[脱敏数据](2026-09-28-dev-contract.json)保留每例状态、来源、判断、耗时和 usage，不包含 Key、提供商配置 ID、执行 ID 或 traceId 明文。

3 条成功结果的判断与观测方向一致，指标、日志和匹配规则的引用均有效，观察文字逐字来自工具摘要，且都有 `CONCLUSION_RENDERED`。另外 3 条来自应用门槛，不能计作模型自主判断。仅文档方法不能回答当前混合窗口的超时比例；C02 仍出现“库存读取超时”这一不准确术语，但没有据此确认整个服务健康。

本轮仅文档共 5 次模型请求、11216 token，Agent 共 9 次、22463 token，均按服务端 usage 记录。此统计不包含首次失败、诊断复查或之前的连接测试，也不等于服务商账单。

关键诊断句子由应用生成，因此本次检查的是系统的证据边界与模型选择能否接通。它不能证明模型自由归因能力提升，也不是生产诊断准确率。首次失败与诊断复查仍保存在本机忽略目录，未用后续成功结果覆盖。

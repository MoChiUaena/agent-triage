# v0.10.0 预览发布验收

2026-10-01，[v0.10.0 预览版](https://github.com/MoChiUaena/agent-triage/releases/tag/v0.10.0)发布。标签和包内清单都指向 `997a64a39d04c6d7e95b3f6ca6f254ea8f8e1bbe`。[常规 CI](https://github.com/MoChiUaena/agent-triage/actions/runs/36838589224)通过主项目 272 项、Starter 42 项，以及 PostgreSQL 与本地模型协议检查；[Petclinic](https://github.com/MoChiUaena/agent-triage/actions/runs/36836063021)和[Petclinic REST](https://github.com/MoChiUaena/agent-triage/actions/runs/36836062994)也完成了 0.10.0 依赖接入验收。

[包内验收](https://github.com/MoChiUaena/agent-triage/actions/runs/36838661170)让 Windows 和 Linux 下载同一份构建产物，验证八进程、五个登记服务、HTTP/JDBC/V3、包内源码、构建版本差异和历史。Windows 检查了 `-CheckOnly` 启动与退出，以及停止标记触发的正常清理；Linux 使用 TERM 停止。两边均确认所有本次端口释放，数据文件保留。发布 ZIP 有 26 个白名单条目，四个主要附件列入 SHA-256 清单；发布后再次对比了五个上传文件的远端摘要。旧 v0.6.0 的发布标识、附件标识与摘要保持不变。

[升级验收](https://github.com/MoChiUaena/agent-triage/actions/runs/36838661227)先验证下载的 v0.6.0 附件，再使用隔离 H2 目录保存完整 V3 记录、加密模型配置和已选模型。新版本原样读取旧记录、密钥与服务配置，两个版本均用保存的密钥完成本地连接探测。旧 V3 未采集的响应分类保持未采集；新增执行和历史清理预览正常。升级基线显式使用同步写盘，保证测试从已落盘的旧数据开始。

发布检查曾在[Windows 升级](https://github.com/MoChiUaena/agent-triage/actions/runs/36837036282)中发现最后一次模型选择丢失；[新增的强制重启检查](https://github.com/MoChiUaena/agent-triage/actions/runs/36837885124)又在 Linux 复现。原因是默认 H2 延迟写盘与强制结束进程的组合。新版默认本地 H2 改为 `WRITE_DELAY=0`；修复后，两平台在强制结束新版进程后都能恢复刚保存的历史、密钥和模型选择。自定义数据源继续按其配置运行；这项测试不等同于断电恢复验收。

产物在干净 CI 构建中生成，上传仅包含演示 ZIP、独立 Starter JAR/POM、可选 Java Agent JAR 和清单；没有上传本机数据库、密钥、日志或测试 JSON。升级和公开项目检查使用固定规则或本地协议服务，没有调用付费模型。新增观测令牌、响应分类和异步传播开关保持默认关闭，包内 `OBSERVATIONS.md` 提供显式接入方法。

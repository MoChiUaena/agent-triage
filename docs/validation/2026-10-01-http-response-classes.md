# HTTP 响应分类验收

2026-10-01，主项目 272 项与 Starter 30 项测试在 [Windows / Ubuntu CI](https://github.com/MoChiUaena/agent-triage/actions/runs/36813147898)中通过。Starter 显式开启 `response-status-counts` 后，V3 服务窗口和接口摘要记录六个固定计数；无法取得最终状态的异常记为未知，异步请求在完成后计数。默认关闭时仍输出原有 V3 字段，V1/V2 不增加分类。Agent 拒绝缺字段、负数、非整数、合计错误及接口与窗口不一致的数据。旧历史缺少分类时显示未采集。

[公开 Petclinic REST 验收](https://github.com/MoChiUaena/agent-triage/actions/runs/36813676867)沿用固定上游提交和原业务文件。主人详情两次 200 与一次 404 形成 2 次 2xx、1 次 4xx；针对 404 的提问现在读取窗口证据，但仍返回证据不足。默认关闭的辅助入口分别制造业务异常 500 和对独立本机服务的调用超时 504：两者各记 1 次 5xx，只有后者增加下游超时计数并支持超时影响判断。500、504 来源于验收辅助入口，不能当作原项目的既有业务故障。源码版本一致、版本差异与旧历史快照检查继续通过，全程没有调用模型。

固定规则和本地模型协议使用同一响应证据门槛。4xx、5xx 或未知响应不能仅凭没有下游超时生成完成判断；模型模式在取得指标与日志后由应用结束为证据不足，不再请求最终模型回答。单独询问具体状态码时只显示分布和检查建议。分类计数可以说明影响范围，不能区分 404 的缺失实体、路由或鉴权原因；完整状态码、业务条件与其他运行证据仍需核实。分类计数可进入模型输入，路由、处理类、源码摘要和异常位置仍保持原有本机边界。

该阶段的跨线程检查发现：RestClient 通过请求线程的 `ThreadLocal` 取得观测上下文，工作线程没有该值；直接复制上下文还会让累计耗时和首次异常发生并发写入。后续 [v0.10 验收](2026-10-01-cross-thread-observations.md)实现了显式任务包装、完成截止和 MVC Callable 的可选接入。DeferredResult 的任意生产线程仍需要应用主动包装，不能据此宣称所有异步调用都可自动归属。

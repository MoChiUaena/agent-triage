# HTTP 跨进程调度诊断

[一小时安全点复跑](2026-10-07-safepoint-hour.md)在 Windows 开启组记录到请求阶段延迟超额，故障附近最长安全点约 368 毫秒，不能单独解释全部等待。源码 `c1355b107b26cb5983a1ba4b8e476bff90278138` 在可选 HTTP 时序模式中，让 JVM 之外的 Python 采样器每 100 毫秒记录自身唤醒间隔。它只保留最近 512 次显著空档；失败时按 JVM 报告的墙钟时间输出附近最多八条纯数字记录。默认模式、原请求负载和资源门槛保持不变。

[60 秒四组](https://github.com/MoChiUaena/agent-triage/actions/runs/37640063390)在 Windows/Linux、Starter 关闭／开启状态全部通过。每组完成 480 次请求、420 个响应关闭；四份数值收据按完整源码 SHA、内存明细哈希和关闭样本严格重放通过。[原始数值](samples/2026-10-07-host-scheduling/60s/)和 [SHA256SUMS](samples/2026-10-07-host-scheduling/SHA256SUMS) 保留可复核附件。

采样器心跳与 JVM 分属不同进程。两边同时出现空档可为运行环境停顿提供线索；只在一边观察到空档也不能排除另一个进程受到调度影响。墙钟时间可能调整，样本附近窗口只是近似对齐。短测验证了诊断链路，长时 Windows 故障的原因仍需单独核对。

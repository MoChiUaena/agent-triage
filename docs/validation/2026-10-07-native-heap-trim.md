# Linux 原生堆整理核对

源码 `2898b55d9f06a5edd7c60eaf961d3061de0be084` 在受控 HTTP 测试 JVM 完成原有关闭采样后，单独调用 JDK 21 的 `System.trim_native_heap`，记录同一 PID 的整理前后读数。原 `memory.csv` 和资源增长门槛不包含整理后的读数。

[60 秒运行](https://github.com/MoChiUaena/agent-triage/actions/runs/37618576508)与[600 秒运行](https://github.com/MoChiUaena/agent-triage/actions/runs/37619126906)均为 Linux 关闭／开启两组通过。60 秒每组完成 480 次请求、420 个响应关闭；600 秒每组完成 4,800 次请求、4,200 个响应关闭。数值附件按完整源码 SHA、工作流运行编号、原关闭样本和 CSV 哈希分别重放通过。

| 时长 | Starter | RSS 整理前 → 后 MiB | 匿名页前 → 后 MiB | NMT 非堆提交前 → 后 MiB |
| --- | --- | ---: | ---: | ---: |
| 60 秒 | 关闭 | 263.70 → 227.86 | 237.10 → 201.25 | 154.57 → 154.57 |
| 60 秒 | 开启 | 285.09 → 242.93 | 258.48 → 216.32 | 159.53 → 159.53 |
| 600 秒 | 关闭 | 304.34 → 253.39 | 277.74 → 226.79 | 178.33 → 157.96 |
| 600 秒 | 开启 | 349.90 → 268.70 | 323.27 → 242.07 | 172.42 → 172.42 |

整理后 RSS 分别下降约 35.84、42.16、50.95 和 81.20 MiB，下降主要出现在匿名页。600 秒的原有预热后 RSS 峰值增量分别为关闭组 30.54 MiB、开启组 61.59 MiB；整理下降量不能从这两个增长值中直接相减，因为它也包含预热前已经驻留的页。开启组 600 秒整理前后 NMT 非堆提交量相同；关闭组同时下降约 20.37 MiB。读数按顺序采集，非原子快照，也来自两台独立 CI 虚拟机。

结果支持关闭时存在可回收的原生驻留页。它不能指出这些页最初来自哪个库或请求阶段，也不能据此认定没有泄漏或量化 Starter 的生产开销。[Windows 一小时超时](2026-10-07-http-hour-timing.md)仍未解决，短时 Linux 整理实验不能替代长时验收。

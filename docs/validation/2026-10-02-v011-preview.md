# v0.11.0 预览发布验收

2026-10-02，[v0.11.0 预览版](https://github.com/MoChiUaena/agent-triage/releases/tag/v0.11.0)发布，发布标识为 `401757485`。五个上传附件的远端摘要逐一匹配 CI 下载文件，标签与包内清单指向同一代码提交；v0.10.0 的发布标识、标签、附件标识与摘要均保持不变。

本次交付的代码提交为 `ba050630f506136c94f84b08af9d22d28b6a9f06`。九个 Maven 项目统一为 0.11.0，包内离线说明增加无下游的 V4 配置、请求失败分类、容量拒绝和异步边界。

包内验收覆盖八个进程、五个登记服务、HTTP/JDBC/V3、工单源码、构建差异和历史。Windows 验证 CheckOnly 启动与退出、停止标记清理；Linux 使用 TERM。所有本次端口释放，数据文件保留。ZIP 仅有 26 个白名单条目，四个主要附件列入 SHA-256 清单，独立 SDK 与包内 SDK 一致。

升级先验证原发布附件。v0.6.0 保存一条未采集响应分类的 V3 历史，v0.10.0 另保存一条两次 2xx、一次 4xx 的分类历史。新版本逐字段读取相同的完整执行记录，不给旧历史补请求失败计数。已选模型、模型配置、密钥摘要与服务配置保持一致，两个版本均用保存的密钥完成本地连接探测。新版本默认 H2 经强制结束后恢复刚保存的历史、密钥和模型选择；这不是断电恢复或 PostgreSQL 升级验收。

发布检查发现两处问题。原校验器只检查 v0.10 上下文类，删去 v0.11 请求失败类并重算内外摘要后仍通过；新增必需类检查后，同一不完整包被拒绝，正常 v0.11 包和原 v0.10.0 附件均通过。首次[升级检查](https://github.com/MoChiUaena/agent-triage/actions/runs/36999470194)把含 4xx 的记录误设为成功预期；旧版正确返回证据不足。修正预期后，该记录仍无可能原因，完整历史原样保留。生产判断没有为通过测试而调整，后续四条矩阵路径独立运行。

公开项目固定为 Petclinic `67643c4137eb75bfeb177b427f8459c471bdcbd8` 和 Petclinic REST `26a80b7a510af1fda0acdfb45d65aa480bdb7607`，原业务文件保持原样。同步与 Callable 异常可确认请求执行阶段；单纯 5xx、捕获下游超时后的响应、Servlet 超时、迟到调用和原有 404 保持证据不足。正常恢复不抹去冻结窗口内的既有异常，同一次 SQL 失败在数据库与 HTTP 侧分别判断。详细场景见[混合对照](2026-10-02-mixed-public-diagnostics.md)。

本轮使用隔离目录、固定规则或本地模型协议服务，没有读取本机模型配置，也没有调用付费模型。发布清单不包含数据库、模型密钥、日志、测试 JSON 或外部源码副本。新开关仍默认关闭，小时／天级运行、原生内存和其他客户端继续单独验收。

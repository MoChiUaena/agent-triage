# Agent Triage v0.6.0

这一版增加了独立的 SQL 执行阶段失败判断。窗口内必须有查询失败次数、同窗口 `SQL_QUERY_FAILED` 错误事件和对应排障规则，应用才会报告“SQL 执行阶段失败”。它不把 SQL 错误当成连接池耗尽，也不推断锁等待、语法或数据库内部根因。数据库样例和公开 Petclinic 的实际请求已分别验证正常查询、连接获取超时、SQL 错误及恢复；模型模式使用本地协议模拟器。

历史页增加手动旧记录清理。可选择保留天数并预览符合条件的已结束记录，输入确认文字后才提交；数量变化会要求重新预览。排队和运行中的记录、模型设置以及最近 30 天的记录不会被这一操作删除。默认没有后台定时清理，使用前应备份数据库。

## 附件与升级

演示包继续包含订单、库存、数据库、商品和工单样例。附件为演示 ZIP、独立 Starter JAR/POM、可选 Java Agent JAR 与 `SHA256SUMS.txt`。首次运行仍只需 JDK 21，不需要模型密钥；演示包不会自动启用可选 Java Agent。完整解压后运行 `start-demo.ps1` 或 `bash start-demo.sh`。

从 v0.5.0 升级前停止旧进程，备份 H2 数据库和 `data/model-config.key`，或备份 PostgreSQL 数据库。新版本沿用原历史和模型配置；手动清理需明确预览与确认，不会因升级自动执行。旧标签与发布附件保持原样。

项目仍面向本机单实例。它只做只读排查，不执行 SQL 修复或自动扩容；没有多用户鉴权和跨实例任务协调。真实模型调用可能产生服务商费用，公开项目验收使用固定规则及本地协议模拟器。

# Agent Triage v0.10.0

这一版补齐本机项目接入时的上下文路径、观测访问控制和异步请求采集，继续面向本机单实例 Java 服务。

- 服务登记地址支持普通上下文路径；Starter 观测接口可选启用访问令牌，并在轮换期间接受新旧令牌。
- MVC 全局异常处理器接手前可记录业务位置；固定版本的 Petclinic REST 已验证原有接口和源码入口。
- HTTP V3 可选记录响应状态分类。页面展示分布，4xx、5xx 或未知响应不会仅凭“没有下游超时”生成完成判断；具体状态码的根因仍需其他证据。
- Spring MVC 异步请求在完成时计入一次。提供 Runnable / Callable 的显式上下文包装，以及 MVC Callable / WebAsyncTask 的可选传播；并发累计安全，响应完成后的迟到结果不再写入请求。
- 百炼、GLM、Kimi 和 LM Studio 的客户端请求格式补了本地协议回归。真实服务凭据仍只验证过百炼。
- 默认本地 H2 同步写盘，保护刚保存的历史和模型选择；自定义数据源按自己的配置运行。

## 附件

`agent-triage-0.10.0-demo.zip` 包含八进程演示、五个登记服务、工单源码样例、Starter、可选 Java Agent 和离线接入说明。其他附件为独立 Starter JAR/POM、可选 `-agent.jar` 与 `SHA256SUMS.txt`。首次运行只需 JDK 21，Linux/macOS 另需 Bash 和 curl，不需要 Maven、外部数据库或模型密钥。

完整解压后运行 `start-demo.ps1` 或 `bash start-demo.sh`。默认使用固定规则与实际本机观测；响应分类、观测令牌和异步传播开关保持关闭。接入自己的应用时按包内 `OBSERVATIONS.md` 显式开启。演示包不包含本机数据、日志、模型密钥或外部项目副本。

## 从 v0.6.0 升级

先等待在途操作完成并停止旧进程，核对数据后备份 H2 数据库和 `data/model-config.key`；使用 PostgreSQL 时备份数据库并保留同一密钥文件。v0.6.0 的默认 H2 延迟写盘，强制结束时可能丢失最后一笔未落盘设置；v0.10.0 默认改为同步写盘。将备份的数据放入新版本完整解压目录，核对自定义服务端口与项目源码路径，再启动新包。源项目搬迁后需更新绑定目录并重新索引；确认可用前保留原包与备份。

旧历史和模型设置继续沿用，升级不会自动清理记录。已选中的模型服务可能继续保持启用，调用真实模型仍可能产生服务商费用。升级回归使用隔离的 H2 目录与本地协议服务；PostgreSQL 另有常规 HTTP 集成检查。

访问令牌只保护本机观测接口，不提供多用户登录。上下文传播不覆盖任意线程、WebFlux 或完整分布式链路；并发下游累计耗时不能当作请求关键路径。当前仍未发布到 Maven Central，旧标签和附件保持原样。

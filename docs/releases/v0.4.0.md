# Agent Triage v0.4.0 候选版

这一版补充了可选的 JPA 数据库观测。业务应用显式将 Hikari `DataSource` 交给 Starter 包装后，Agent 可以分别查看 HTTP 接口与数据库操作，区分获取连接超时、连接获取失败和 SQL 执行失败。v0.3.0 已发布的标签和附件保持原样。

## 演示包

打包方式延续 v0.3.0：JDK 21，完整解压后运行 `start-demo.ps1` 或 `bash start-demo.sh`。包内五个服务、八个进程和工单源码样例仍可直接体验，首次运行无需 API Key。演示包中的服务默认没有开启 JPA 观测；验证新能力需从源码构建 Starter，并按[Petclinic 接入步骤](../PETCLINIC.md)准备公开项目。这会增加一次公开项目构建，业务源码不需要改动。

源码仓库中构建主项目、样例服务和集成模块后运行 `python scripts/package_release.py`；`python scripts/verify_release.py --source-commit <完整提交SHA>` 核对附件、包内 24 个文件以及工单源码与 class 的构建摘要。发布前工作区须保持干净。独立 Starter JAR/POM 尚未发布到 Maven Central。

## 公开项目验收

[Spring Petclinic 验收记录](../validation/2026-09-30-petclinic-jpa.md)使用固定上游提交和独立本机实例：原有业务请求产生 10 次 JDBC 执行；验收配置里的固定无效查询记录 1 次 SQL 错误；短暂占用单连接后，原有主人详情请求在获取连接阶段超时，释放后恢复为 200。只有获取超时、池满且有等待的采样、错误事件和规则一起出现，才支持连接池耗尽判断。单独 SQL 失败仍返回证据不足。

新版还会把可对应的 lambda 异常位置标为源码方法候选。普通异常栈没有可靠类加载器引用时，构建版本维持未知，页面不会把候选写成确切位置。

## 接入边界与升级

JPA 包装只记录匹配的同步业务请求线程和 `Statement.execute*`；结果集遍历、其他线程以及主动取出底层连接后的调用可能不在窗口内。数据库 `requestCount` 表示观测到的 JDBC 操作数，不等于 HTTP 请求数。Starter 不保存 SQL、参数、请求正文或原始异常；数据库别名只使用 Agent 启动配置中的本机地址和固定观测路径。

Agent 的数据迁移延续 v0.3.0，升级前停止旧进程并备份 `data/triage.mv.db` 与 `data/model-config.key`；PostgreSQL 备份数据库。旧历史保持原内容，新配置默认关闭，不会自动改写业务项目或开启模型调用。当前仍面向本机单实例，没有多用户鉴权或生产遥测适配。

# Agent Triage v0.3.0 候选包

这一版增加[工作区管理](../WORKSPACE.md)：历史分页与筛选、已结束记录的确认删除、运行统计和服务观测状态。v0.3.0 尚未公开发布，已发布的 v0.1.0 与 v0.2.0 附件保持原版本。

## 使用

构建与打包命令和 [v0.2.0](v0.2.0.md) 相同，各模块版本为 0.3.0。`python scripts/package_release.py` 在 `target/release` 输出演示 ZIP、独立 Starter JAR/POM 和校验清单；`python scripts/verify_release.py` 核对三个交付附件及包内 13 个文件。

完整解压后，Windows 运行 `powershell -ExecutionPolicy Bypass -File .\start-demo.ps1`，macOS/Linux 运行 `bash start-demo.sh`。需要 JDK 21，Bash 还需 curl。六个进程与端口偏移 0、2、4、6、8、9 延续原配置。

打开页面后，从“全部记录与筛选”进入工作区。历史记录可以逐页查看，按问题、服务、状态、模式与日期筛选；“查看”打开保存结果。删除窗口显示目标记录，排队和运行中的记录不能删除。

运行统计支持近 7、30、90 天及服务筛选，显示状态分布、有效终态耗时、工具与模型调用、完整／部分已知／缺失用量。服务状态分别显示实际观测、空窗口、接口不可用与合成演示，保留协议、窗口和检查时间。

## 升级

数据库 V3 迁移为历史增加查询索引列，启动时分批回填旧数据，不重写原始执行 JSON。升级前停止旧 Agent，并一起备份 `data/triage.mv.db` 与 `data/model-config.key`；PostgreSQL 用户备份数据库。原服务与模型配置继续读取，旧历史仍可打开。

删除记录不可通过页面恢复，没有自动清理任务。统计是执行与已知用量记录，不表示诊断准确率或费用金额。默认首次启动使用固定规则；已启用模型可能计费，查询工作区本身不发起模型请求。

包内不含本机历史、日志或密钥。当前仍面向本机单实例，Starter 的同步 HTTP 与显式 JDBC 接入范围延续 v0.2。

# Agent Triage v0.3.0

这一版把本机源码接入加入排查流程：按实际处理方法找到接口入口，查看业务错误对应的源码行，并核对运行 JAR 与当前源码的构建摘要。同时提供完整历史、接口筛选、运行统计和接入检查。

## 下载与启动

[预览发布](https://github.com/MoChiUaena/agent-triage/releases/tag/v0.3.0)提供演示 ZIP、独立 Starter JAR/POM 和 SHA-256 清单。首次运行只需 JDK 21，无需 Maven 或 API Key；macOS/Linux 还需 Bash 与 curl。

完整解压后，Windows 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-demo.ps1
```

macOS/Linux 运行 `bash start-demo.sh`。打开 <http://127.0.0.1:18080>，按 Ctrl+C 停止本次启动的全部进程。数据和日志保留在解压目录。

| 进程 | 默认端口 | 用途 |
|---|---|---|
| Agent | 18080 | 页面、排查与历史 |
| 订单／库存 | 18082／18084 | 正常请求与库存超时 |
| 数据库样例 | 18086 | 连接池耗尽与恢复 |
| 商品／价格 | 18088／18089 | Starter HTTP V1 与 JDBC V2 接入 |
| 工单／分配 | 18090／18092 | MVC HTTP V3、错误位置与源码核对 |

七个可执行 JAR 启动八个进程，Agent 登记五个服务。端口占用时可使用 `start-demo.ps1 -BasePort 18180` 或 `bash start-demo.sh 18180`，各端口偏移为 0、2、4、6、8、9、10、12。Windows 的 `-CheckOnly` 检查启动后立即停止。

## 体验源码排查

按照包内 `SOURCE_DEMO.md`，先请求工单的 `/api/tickets/summary` 与 `/api/tickets/T-1`。前者正常，后者通过实际 HTTP 调用产生 504：分配服务延迟 700 ms，工单读取超时为 250 ms。

在“项目源码”登记包内 `projects/ticket-service`，绑定工单服务，点击“检查接入”。返回排查页，分别选择两个接口并勾选“本次检索源码”：正常接口没有下游超时，详情接口显示超时证据、`AssignmentGateway.lookup` 的业务错误位置和调用关系。

包内源码与工单 JAR 来自同一构建。修改源码并重新索引后，版本核对会提示摘要不同，保留运行诊断并停止采用该版本的调用关系；已有历史保留原快照。模型读取源码需要另行授权，整个默认样例不调用模型。

历史页面支持分页、服务与接口筛选、运行统计和已结束记录的确认删除。统计记录执行与已知用量，不表示诊断准确率或费用金额。

## 从源码构建

使用 JDK 21，依次构建主项目、订单、库存、数据库和集成模块，再打包：

```powershell
.\mvnw.cmd -B -ntp verify
.\mvnw.cmd -B -ntp -f sample-service/pom.xml verify
.\mvnw.cmd -B -ntp -f inventory-service/pom.xml verify
.\mvnw.cmd -B -ntp -f database-service/pom.xml verify
.\mvnw.cmd -B -ntp -f integrations/pom.xml verify
python scripts/package_release.py
python scripts/verify_release.py --source-commit <当前提交的完整SHA>
```

打包要求工作区干净，输出位于 `target/release`。校验脚本核对三个交付附件、包内 24 个文件，以及工单源码和实际 class 文件的摘要。Starter 尚未发布至 Maven Central，安装方法见[Starter 说明](../STARTER.md)。

## 升级与范围

数据库 V3/V6 为历史增加索引，并分批回填旧数据，不重写原执行 JSON。升级前停止旧 Agent，将 `data/triage.mv.db` 与 `data/model-config.key` 一起备份；PostgreSQL 用户备份数据库。旧历史与模型配置继续读取。页面删除不可恢复，没有自动清理任务。

发布包不含本机历史、日志、密钥或用户源码。当前面向本机单实例，没有多用户鉴权；观测需要 Starter 或适配已公布的接口，不会自动接管任意日志或 Actuator 数据。静态调用关系是核查线索，不能证明跨服务内部根因。其他供应商预设和任意外部业务项目尚未逐一验证。

v0.1.0 与 v0.2.0 的标签和附件保持原版本。

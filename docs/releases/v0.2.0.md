# Agent Triage v0.2.0

从 [v0.2.0 预览发布](https://github.com/MoChiUaena/agent-triage/releases/tag/v0.2.0)下载演示 ZIP、独立 Starter JAR、POM 和 `SHA256SUMS.txt`。本页说明启动、构建与使用范围；v0.1.0 附件保持原版本。

## 本次内容

- 服务白名单与页面切换，支持 HTTP V1 和数据库 V2 只读观测。
- 真实 HikariCP/H2 连接池耗尽、SQL 锁等待与恢复实验。
- 主动取消、证据保留、输入／输出 Token 和用量完整程度。
- Spring Boot Starter 与独立商品、价格查询应用。
- 具体的连接、接口版本、字段契约和窗口保留错误提示。

## 构建

使用 JDK 21，在干净的仓库根目录运行：

```powershell
.\mvnw.cmd -B -ntp verify
.\mvnw.cmd -B -ntp -f inventory-service/pom.xml verify
.\mvnw.cmd -B -ntp -f sample-service/pom.xml verify
.\mvnw.cmd -B -ntp -f database-service/pom.xml verify
.\mvnw.cmd -B -ntp -f integrations/pom.xml verify
python scripts/package_release.py
```

macOS/Linux 使用 `./mvnw` 替代 `.\mvnw.cmd`。演示包写入 `target/release/agent-triage-0.2.0-demo.zip`，同目录有 `SHA256SUMS.txt`。清单记录源码提交、文件摘要和打包时工作树是否干净；`--allow-dirty` 只用于本地试包，不用于交付。

同目录另有可单独下载的 `triage-spring-boot-starter-0.2.0.jar` 与 `.pom`。校验清单只覆盖实际交付的 ZIP、Starter JAR 和 POM；旧版录像保留在 v0.1.0 发布中。运行 `python scripts/verify_release.py` 可核对三个附件、包内 13 个文件和 Maven 坐标。

压缩包只包含五个可执行 JAR、一个普通 Starter JAR、Starter POM、服务配置、启动脚本、说明、许可证和清单，共 13 项。不会从 `data/`、日志目录或本机模型配置中收集文件。

## 启动与体验

完整解压后，Windows 运行 `powershell -ExecutionPolicy Bypass -File .\start-demo.ps1`，macOS/Linux 运行 `bash start-demo.sh`。首次不需要 Maven、外部数据库或模型密钥。

| 进程 | 默认端口 | 操作 |
|---|---|---|
| Agent | 18080 | 页面选择服务、排查与查看历史 |
| 订单 | 18082 | 页面生成正常或库存超时请求 |
| 库存 | 18084 | 为订单与商品提供实际 HTTP 下游 |
| 数据库账户样例 | 18086 | 页面触发池耗尽、释放连接和验证恢复 |
| Starter 商品 | 18088 | 访问 `/api/products/demo` 产生请求 |
| Starter 价格 | 18089 | 访问 `/api/prices/demo` 产生 JDBC 查询 |

四个服务登记在 `config/services.yml`。商品与价格服务没有实验控制接口；商品共享库存，因此库存延迟也会影响商品请求。组件接入方法见 [Starter](../STARTER.md)。

可通过 PowerShell `-BasePort 18180` 或 Bash 第一个参数 `18180` 改端口，其他端口使用偏移 2、4、6、8、9。Ctrl+C 停止本次启动的六个进程，数据和日志保留。Windows `-CheckOnly` 检查四个登记服务都可读取后立即停止。

模型设置仍可在页面添加。已保存的启用模型可能产生费用；取消只停止本地等待，不能保证服务方终止已接受的请求。历史库与加密密钥需要一起备份。

## 使用范围

当前仍面向本机单实例，没有生产鉴权、多实例协调或自动修复。Starter 只支持同步 Spring MVC 请求、Spring 提供的 RestClient.Builder 和显式 JDBC 回调；不自动采集 WebFlux、跨线程调用、JPA 或任意日志。未做新的真实模型留出评测，不能把本次集成通过解释为诊断准确率提高。

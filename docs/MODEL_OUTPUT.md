# 模型判断与结论生成

2026-09-27 的自由文本对照出现了“库存不可用”“服务整体健康”等未被观测证明的说法，也出现了 traceId 误写。新版保留模型的工具选择，但不再让模型编写关键诊断句子。

模型最终只返回三个字段：

```json
{
  "assessment": "DOWNSTREAM_TIMEOUT_OBSERVED",
  "evidenceIds": ["本次指标 ID", "本次日志 ID", "对应规则 ID"],
  "nextChecks": ["INSPECT_INVENTORY_LATENCY", "CORRELATE_TRACE"]
}
```

HTTP 观测使用“本窗口发现下游调用超时”“本窗口未发现下游调用超时”“证据不足”三种判断。数据库观测使用 `DB_POOL_EXHAUSTION_OBSERVED`、`NO_DB_POOL_EXHAUSTION_OBSERVED` 和证据不足，schema 按服务类型提供；两类判断不能混用。检查项从固定列表选择，方向错误、缺少证据、未知检查项或额外自由文本都会被拒绝。

数据库耗尽判断要求获取连接超时、同次采样的池满与等待、对应阶段错误和数据库规则同时成立，且指标与日志中的窗口请求数及错误计数一致。SQL 查询失败不能替代获取连接超时。数据库检查项包括 `INSPECT_DB_CONNECTION_HOLDERS`、`VERIFY_DB_POOL_LIMITS`、`INSPECT_DB_QUERIES`，沿用相同的调用、反馈和输出限额；应用仍只展示有效候选中的前两项。[数据库观测说明](DATABASE_POOL.md)列出了采集范围。

成功判断必须同时引用指标、日志和对应判断的规则。每轮工具返回后，应用按来源列出已收集的可选 ID，并分别标出超时与正常规则，减少漏选或抄错引用。拒绝原因区分未知字段、字段类型、未知检查项、无效引用和缺失规则；错误消息不回显模型文本或异常中的标识符。

检查项还要与当前证据匹配。成功判断已取得窗口指标、日志和规则，不能再要求重复收集这些内容；没有错误事件 traceId 时，不能建议关联已有 traceId。模型省略引用也不能把已采集的观测变成“缺失”。不符合条件的选择返回 `MODEL_CHECKS_MISMATCH`，不会悄悄替换成其他建议。有效选择以代码形式保存在 `modelExecution.nextChecks`，旧记录缺少此字段时仍可读取。

工具参数按大小、JSON、字段、服务、窗口和查询分类校验。整批请求全部通过后才执行工具；首次无效时返回固定错误说明与原始 schema，允许模型更正一次。再次无效则失败，未注册工具与重复调用 ID 不参与更正。更正不会提高现有调用次数或时限；`TOOL_ARGUMENTS_REJECTED` 只包含应用生成的分类和消息。

必需证据或引用不齐时返回 `MODEL_MISSING_EVIDENCE`。应用只有在剩余额度足以完成查询和输出时，才发送一次完整性反馈；模型自己补齐工具或引用，应用不代填证据。未知 ID、格式错误及矛盾判断仍立即拒绝。

必需来源齐全后，下一轮请求设置 `tool_choice=none`，只生成最终选择。兼容接口若仍返回工具调用，网关的次数和重复请求限制继续生效，不以忽略多余请求伪装成功。

LIVE 检索默认提供本服务的正常与超时基础参考，另按关键词提供证据说明，召回原因在证据中标明。这些文档仅是规则，当前状态仍由窗口指标与日志支持。

有效检查项按应用策略排序并展示前两项：超时窗口优先关联已有 trace、核对库存处理耗时，再核对时限与资源；无超时窗口优先补充缺失资源观测与具体慢请求。只排列模型选中的项，不插入新项。原始选择保存在 `requestedNextChecks`，展示项保存在 `nextChecks`，并记录 `CHECKS_PRIORITIZED`。这是应用排序，不是模型排序能力。

观察直接采用工具生成的窗口摘要，可能原因和不确定性使用限定范围的应用措辞；模型不复制 p95、请求数或 traceId。具体 traceId 保留在原始日志证据中。成功生成时记录 `CONCLUSION_RENDERED`，页面标明“模型选证据 · 应用生成措辞”。

对外 `diagnosis` 的结构与既有页面保持一致。旧执行记录不重写，缺少新字段时仍可读取。此前首次结果作为历史保留；完整性反馈与应用排序修订使用 [v4 案例](evaluation/cases-v4.json)和[v4 标准](evaluation/rubric-v4.md)验证。

# Issue 分诊

在“研发协作”选择仓库，点击 Issue 条目的“分诊”，或按编号读取。页面先展示脱敏上下文；可补充最多三个仓库相对 Java 文件路径，再点击“重新读取上下文”。确认内容后生成报告，最近 20 份可从历史重开。

上下文包含 Issue 标题、正文、标签、现有负责人，默认分支固定提交的近期五次提交，以及最多十位贡献者。源码只读取正文明确提到或手动补充的相对路径，不搜索整个代码库。自动化账户不作为负责人候选；贡献者名单不代表可分配权限、职责或当前工作量。评论未读取时会显示缺口。

预览在内存中保存五分钟，最多 40 份，重启后失效。生成报告前会再次核对 Issue 内容；内容或启用模型版本变化时需要重读。若生成过程中 Issue 更新，报告保留预览快照并提示重新核对。源码和提交固定到预览中的 SHA，之后的推送不会改写历史。

默认生成基础分诊，不发送数据。基础分类只参考明确标签，优先级没有对应标签时保持待定，并提供复现、环境和影响范围的核查清单。

选择“使用模型建议”才会把页面所示的脱敏 Issue、代码、提交、贡献者和缺口发送给启用模型。页面显示模型名称与服务地址，配置沿用[模型设置](MODELS.md)。只调用一轮，最多等待 30 秒；不执行工具或修改 GitHub。模型可以提出分类、优先级、待补充信息、行动项和负责人候选，结果仍需人工确认。

模型引用必须属于本次证据；负责人必须在已读取的贡献者中，并引用对应证据。无效输出、工具请求、超时或服务失败时丢弃模型建议，保留基础报告与已知用量。超时后的用量未知，不表示没有计费。协议链路已用本机模型接口验证，具体模型的建议质量需要结合实际问题核对。

Issue 正文最多 12,000 字符、200 行；最多三个 Java 文件，每份文件最多 100,000 字节，片段最多 40 行、2,500 字符。裁剪保持目标行，目标行自身超限时显示缺口。完整源码只在内存处理；报告保存脱敏片段、读取时间、提交、模型来源与用量，不保存 API Key 或 GitHub Token。

所有外部 GitHub 请求均为 GET。模型建议不会自动变更标签、指派负责人、评论、关闭问题或执行修复。移除仓库登记会级联删除本机分诊报告。

| 方法 | 路由 | 用途 |
|---|---|---|
| POST | `/api/development/repositories/{id}/issue/previews` | 读取上下文，正文为 `{"number":2,"codePaths":[]}` |
| POST | `/api/development/repositories/{id}/issue/reports` | 生成报告，正文为 `{"previewId":"预览UUID","useModel":false}` |
| GET | `/api/development/repositories/{id}/issue/reports` | 最近 20 份报告 |
| GET | `/api/development/issue/reports/{reportId}` | 查看保存的报告 |

接口沿用本机同源保护，POST 需要 `X-Triage-Development: 1`。GitHub 权限沿用仓库接入；私有仓库源码读取还需要 Contents 只读权限。

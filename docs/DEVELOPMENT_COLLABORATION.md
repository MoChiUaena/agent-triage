# 研发协作功能计划

参考 [DevFlow 的公开功能说明](https://xiaolincoding.com/project/devflow.html)，Agent Triage 在 Java 服务排查之外提供 GitHub 研发协作。仓库概览、CI 排障、PR 审查、Issue 分诊与协同工作流已合入主分支；知识、记忆、报告与操作草稿继续按下方计划推进。

## 当前差距

| 能力 | 当前状态 |
|---|---|
| 仓库健康概览 | 已实现仓库登记、真实 Issue／PR／默认分支 CI 列表、快照与失败提示，以及可保存的规则健康摘要（R0：来源与抽样范围标注、过期提示、失败工作流与本机记录统计）；尚不做版本发布决策或模型摘要 |
| CI 排障 | 已实现失败作业、日志读取或粘贴、脱敏证据、本机规则报告，以及用户显式启用的模型建议（独立预览确认、引用校验、失败保留规则报告）；不自动重跑 CI 或修改代码 |
| PR 风险审查 | 已实现固定 SHA 差异、行级规则提醒、对应提交 CI、正文 Issue 引用、本机报告历史，以及用户显式启用的模型建议（差异范围预览、源码单独授权、文件行号与 SHA 校验、失败保留规则报告），并可选附带受限本机源码上下文（S1：变更行版本核对、静态调用候选与多实现候选、歧义明确标识）；完整调用链分析仍在既有源码索引能力范围内 |
| Issue 分诊 | 已有版本化上下文（含最近五条评论）、基础分类与可选模型建议、优先级、待补充信息、带引用行动项，以及受贡献者与 CODEOWNERS 范围限制的负责人候选和可选本机符号候选（S1）；尚不自动处理 GitHub 或复现问题 |
| 协同工作流 | 已有固定 PR 模板、依赖与状态、失败跳过、版本核验、一次补查、综合报告、取消和重启恢复；尚无任意任务图或自主修复 |
| 对话与长期记忆 | 有执行历史，没有追问上下文或经确认的项目记忆 |
| 研发周报 | 已实现按仓库与日期范围生成的研发活动报告（R1：提交／Issue／PR／CI 与本机分析记录按日分组、来源跳转、待处理事项、读取缺口与 Markdown 导出，规则汇总）；可选模型摘要、回写知识库与更长范围的有界活动缓存仍在后续计划 |
| 操作草稿 | 已实现本机操作草稿（W1 首轮）：从已保存 Issue 分诊 / PR 审查报告生成评论与标签草稿，可编辑（修订校验）、丢弃，明确「草稿 · 未执行」；评论与标签草稿已可经页面确认执行（W2：独立写入凭据、执行预览与二次核对、防重复提交、超时先核对远端、本机审计）；创建/关闭 Issue 草稿为后续扩展 |
| 知识检索 | 已有项目知识导入、版本管理、关键词检索与可选向量混合检索（K1/K2/K3）；研发分析消费知识资料仍在后续计划中 |

现有模型配置、工具限额、SSE、证据引用、历史和本机源码检索可以复用。GitHub 的当前状态与代码版本须直接读取，历史资料和经验再进入知识检索。

## 推进顺序

1. **仓库接入与概览。** 固定导航增加“研发协作”。登记 GitHub 仓库，展示最近的开放 Issue、PR 和默认分支工作流；保存读取时间、来源链接和最后一次结果，区分未读取、失败与空列表。先支持公开仓库以及启动配置中的可选 Token，凭据不进入数据库、页面响应或日志。
2. **CI 排障。** 从失败工作流进入具体作业，读取有界日志，提取错误块、失败步骤和文件位置。生成引用原始日志行的分析报告，用户可以继续核对原因和修复步骤。
3. **PR 审查。** 读取固定 head SHA 的文件差异，结合关联 Issue 和 CI，检查 Java 变更风险。结果保留文件、行号、版本及证据，无法读取完整差异时显示缺口。
4. **Issue 分诊。** 分析问题描述、相关代码和近期改动，给出分类、优先级、待确认项和行动清单。负责人只能从已有贡献者或用户指定范围中提出候选。
5. **协同工作流。** 将仓库、Issue、PR、CI 分析组合成有依赖的任务；显示计划、任务状态和综合报告，处理失败跳过、结论冲突与有界补查。
6. **知识与记忆。** 导入仓库文档和已确认报告，增加关键词／向量混合检索；支持同一任务的追问、历史摘要，以及用户确认后才可跨任务复用的项目经验。
7. **报告与操作草稿。** 按日期汇总研发活动和待办；评论、标签、创建或关闭 Issue 先形成可编辑草稿，经页面确认后执行并保存审计记录。

每个阶段交付页面、API 和一条真实使用链路，提交独立改动。必要的功能回归随实现完成；已有长测继续在后台运行，功能开发不以重复长测为前置。

## 第一阶段交付条件

- 从固定导航进入研发协作，登记 `owner/repository` 或标准 GitHub 仓库链接。
- 从 GitHub 实际读取 Issue、PR、CI，显示条目来源和更新时间。
- 页面说明列表范围，开放 Issue 与 PR 不混算，未读取的 Actions 不显示为成功或零失败。
- 重启后保留仓库与最后一次快照；更新失败仍能查看旧结果及其时间。
- 请求仅访问固定 GitHub API，外部操作全部只读；本机登记和刷新接口沿用同源保护。

## CI 模型辅助分析（A1）

在规则报告之外，用户可以在 CI 排障报告卡片显式启用模型建议：

1. **预览发送范围。** 「预览发送范围」生成十分钟有效的预览：已脱敏错误块（编号与日志行号）、失败作业、尝试与提交 SHA、规则报告已识别的阶段，以及逐条裁剪说明（完整日志其余行、其他作业与尝试、仓库源码与项目文档都不发送）。预览确认前不发送任何内容。
2. **确认后生成。** 勾选确认后才调用模型；输出须通过格式与引用校验——只能引用本次发送的 `CI-LOG-n` 日志块，须区分与规则阶段的关系（一致 / 补充方向 / 不一致需人工核对 / 证据不足）、原因假设与下一步待验证事项。假设不是已确认根因。
3. **失败保留规则报告。** 模型失败、超时、输出无效或引用未知日志块时保存状态记录但不产生建议；规则报告与既有结论永不改写，不自动重跑 CI 或修改代码。跨报告、过期预览或模型配置变化一律拒绝并提示重新预览。

同一报告的模型建议历史（最近 20 条）可回看。模型走当前启用的聊天模型服务，费用只按模型返回的 usage 记录已知值；日志脱敏沿用规则报告生成时的结果，预览与发送不会扩大范围。API：`GET /api/development/ci/model-option`、`POST /api/development/ci/reports/{id}/model/previews|analyses`、`GET …/model/analyses`。项目知识资料（K2/K3）接入模型建议为后续增强。

## PR 模型辅助审查（A2）

在 PR 规则报告之外，用户可以在 PR 审查报告卡片显式启用模型建议：

1. **预览差异范围。** 预览按报告冻结的 base/head SHA 重新读取差异，只发送完整 hunk（逐行脱敏；单文件最多 6000 字符、总量 40000 字符、最多 20 个文件，超出部分逐项列入裁剪说明；GitHub 未提供补丁的文件不发送），并随补丁一并发送规则提醒、Head 检查状态与正文 Issue 引用。预览与分析前都核对 PR 当前 base/head——PR 一旦更新，旧报告的预览与分析即被拒绝并提示基于当前 PR 重新生成。
2. **双重确认后生成。** 需分别勾选一般发送确认与源码补丁外发确认（codeConfirmed）后才调用模型。输出经文件、行号与 SHA 校验：引用文件必须在发送范围内，行号必须落在所发 hunk 的 NEW/OLD 行区间，reviewedSha 必须等于本次 head SHA；置信度限定 HIGH/MEDIUM/LOW。输出区分变更意图、潜在风险与测试缺口，全部是待核对假设。
3. **失败保留规则报告。** 模型失败、超时、输出无效或引用越界时保存状态记录但不产生建议；规则报告与既有结论永不改写。模型建议不构成合入批准，不会自动合并、批准或修改代码。

API：`GET /api/development/pr/model-option`、`POST /api/development/pr/reports/{id}/model/previews|analyses`、`GET …/model/analyses`。项目约定（K2/K3）接入为后续增强。

### 可选本机源码上下文（S1 接入）

生成 PR 模型预览时可指定一个已登记本机 Java 项目（及其索引 revision）。上下文按报告冻结 SHA 的补丁构建，逐文件给出明确状态：

- **MATCHED（版本核对通过）**：补丁变更行与本机文件抽样比对一致（忽略行尾差异；文件其余部分未逐一核对）。仅此时发送限量符号摘录（每文件最多 4 个、每段 1600 字符）、静态反向调用候选（每文件最多 10 条；重载未分辨时标记 AMBIGUOUS）与接口多实现候选（最多 6 个）。
- **VERSION_MISMATCH**：变更行与 PR head 不一致——停止采用该文件的本机上下文，不发送摘录，引用将被拒绝。
- **NOT_INDEXED / UNAVAILABLE**：路径不在所选索引，或本机文件漂移、含凭据被排除——明确说明且不发送。

上下文全部标注为静态候选：反射、动态代理等未知路径保持未知，模型不得声称已验证运行时行为。引用上下文需用 side=CONTEXT 且行号落在所发摘录范围内，越界引用被拒绝。源码内容外发受 codeConfirmed 约束；索引 revision 不一致返回 409。未选择源码项目时行为不变。

## Issue 上下文补全（A3）

在既有 Issue 分诊上补充三类有界上下文，全部随预览展示读取范围与缺口：

1. **最近评论（有界）。** 读取最近五条评论（每条 2,000 字符、60 行上限，脱敏后作为 COMMENT 证据）；评论中提到的 Java 路径并入代码候选（与正文路径合计仍限三个，正文优先）。评论纳入预览指纹——评论变化后旧预览与生成都被拒绝并要求重新读取。评论为不可信用户内容：其中提及的账号与提交明确不构成因果结论或负责人推荐。
2. **可选本机符号候选（S1 复用）。** 预览时可指定已登记本机 Java 项目及其索引 revision：从标题、正文与评论提取标识符检索本机索引，最多六条 SYMBOL 静态候选。版本边界明确标注——索引版本未与任何提交核对，不证明执行路径；revision 不一致 409，项目不存在 404。反射等未知路径保持未知。
3. **CODEOWNERS 负责人线索。** 按默认分支固定 SHA 读取 CODEOWNERS（有界解析：50 条规则、仅 @用户 条目、简化匹配），命中候选路径的规则给出负责人候选与规则证据；候选范围 = 贡献者 ∪ CODEOWNERS，模型提名范围外账号被拒绝。候选不代表已同意处理此 Issue，不推断工作量或分配权限。

评论端点或 CODEOWNERS 不可用时降级为缺口说明，分诊仍可生成。分诊不等于复现成功；近期提交列表延续既有边界（未证明与 Issue 有关）。

## 仓库健康摘要（R0）

研发协作页仓库卡片可按规则生成可保存的健康摘要，汇总当前概览快照与本机已保存分析记录：

1. **来源与范围逐项标注。** 每个区段标明快照读取时间、抽样范围（Issue／PR 最多 20 条，截断时明确“覆盖不完整”）与统计口径；生成时未重新访问 GitHub、不调用模型。快照过期或上次读取失败时，摘要顶部提示先“更新 GitHub 状态”，但保留当次结果与范围。
2. **失败项与覆盖缺口。** WORKFLOWS 区段统计默认分支最近 20 次中的失败工作流（最多列 10 条并链接原文）；区段不可用（如 Actions 权限拒绝）时写入明确缺口，不代表其没有失败项。抽样列表从不称为全量统计。
3. **本机记录与边界。** 按 CI 排障／PR 审查／Issue 分诊统计已保存报告数量与最新一条标题（每类 20 条窗口），声明不代表仓库全部状态；既有报告结论只引用数量与时间，不改写任何版本。无模型时规则汇总完全可用。

支持手动生成、按仓库列出最近 20 份摘要历史与单条重开；移除仓库登记时摘要随级联一并删除。可选模型摘要为后续增强。

## 研发活动报告（R1）

研发协作页仓库卡片可按日期范围（单日日报或多日周报，最多 31 天，结束日期不晚于今天）生成可保存的研发活动报告。数据来源只有两类：仓库概览快照（自本批起快照含默认分支最近 20 条提交的抽样区段）与本机已保存的分析报告；生成时不重新访问 GitHub、不调用模型。

1. **按日活动明细。** 提交、Issue、PR、工作流（来自快照抽样，各最多 20 条；Issue 与 PR 仅开放状态）与 CI 排障／PR 审查／Issue 分诊本机报告（各 20 条窗口）按本地日期分组；每项活动带 GitHub 来源链接，本机报告附类型与报告 ID，可在页面一键重开对应报告。
2. **待处理事项与缺口。** 汇总当前快照抽样内的失败工作流、开放 Issue 与开放 PR（各最多 10 条）；区段不可用、达到抽样上限被截断或旧版本快照缺少提交区段时逐条写入读取缺口。空日期范围（各区段可用但无匹配活动）与读取失败严格区分，前者是明确说明，后者是缺口。
3. **Markdown 导出与边界。** 单条报告可导出为 Markdown（本机下载，内容按保存的 payload 确定性渲染，含来源链接、缺口与说明）；报告不自动发送邮件、评论或任何 GitHub 写操作。「回写知识库」选项未启用：后续版本将按 K1 版本机制显式导入为项目知识，默认关闭，不覆盖已有知识版本。可选模型摘要为后续增强；覆盖更长日期范围的有界活动缓存（记录读取时间、范围与分页位置）亦为后续按需实现，不做持续全量同步。

API：`POST /api/development/repositories/{id}/activity-reports`（body `fromDate`/`toDate`）、`GET …/activity-reports`（最近 20 份）、`GET /api/development/activity-reports/{id}`、`GET /api/development/activity-reports/{id}/markdown`（`text/markdown`）。报告存于 V21 `repository_activity_reports`（payload JSON，随仓库登记 `ON DELETE CASCADE` 清理）。

## GitHub 操作草稿（W1 首轮）

研发协作页仓库卡片可将已保存的分析报告转换为本机草稿。首轮支持评论草稿与标签草稿；创建 / 关闭 Issue 草稿为后续扩展。

1. **依据与目标版本。** 草稿必须以同一仓库已保存的 Issue 分诊报告（评论 / 标签）或 PR 审查报告（评论）为依据：目标对象（Issue / PR 编号、标题、链接）、依据报告 ID 与标题快照、目标版本（PR 为 head SHA，Issue 为更新时间）随草稿保存；编辑正文或标签不改变来源关系。评论正文由报告内容生成模板（含“未执行任何 GitHub 操作”边界句），标签草稿默认取分诊结论的类别标签，均可在页面上继续编辑。
2. **本机生命周期。** 草稿可编辑（正文最长 20,000 字符；标签每次添加 / 移除各最多 10 个、单个最长 64 字符，不允许重复或同时添加又移除）与丢弃；编辑采用修订号乐观校验，过期修订返回 409。草稿保存在 V22 `operation_drafts`（payload JSON，随仓库登记级联删除），丢弃后不再出现在列表但记录保留可查。
3. **边界。** 生成与编辑草稿只读本机报告与登记，不发起任何 GitHub 请求（有回归断言 fixture 侧只有 GET），页面与 API 响应均标注「草稿 · 未执行」；发布、执行与审计属于 W2，当前不存在任何 GitHub 写客户端。模型建议不会自动成为草稿或发布；跨仓库依据被拒绝。

API：`POST /api/development/repositories/{id}/drafts`（body `kind`/`basisReportId`）、`GET …/drafts`（未丢弃草稿，最近 50 条）、`GET /api/development/drafts/{id}`、`PUT /api/development/drafts/{id}`（body `revision`/`body`/`addLabels`/`removeLabels`）、`POST /api/development/drafts/{id}/discard`。

## 确认执行与审计（W2 首轮）

评论与标签草稿可经页面确认后执行。执行使用与读取 Token 相互独立的写入凭据（启动配置 `triage.github.write-token`，默认不配置即全部执行端点拒绝；超时默认 8 秒，可用 `triage.github.write-timeout-seconds` 调整），页面通过 `GET /api/development/drafts/write-option` 展示可用性。

1. **执行预览与二次核对。** `POST /api/development/drafts/{id}/execution-previews` 用写入凭据读取仓库推送权限与目标当前状态：无推送权限 403；Issue 已关闭或更新时间与草稿保存的目标版本不同、PR head 变化均 409（提示目标已变化）。预览展示操作、目标、内容（标签草稿显示当前标签 → 执行后标签）、影响与边界说明，十分钟内有效且只能使用一次。执行时重新核对目标状态，预览后被修改（草稿修订变化）或目标再次变化都会拒绝。
2. **防重复与不确定结果。** 执行前把草稿原子占位为 EXECUTING（已执行 / 丢弃 / 占位中的草稿均拒绝执行），成功后置 EXECUTED 并锁定编辑；失败或结果不确定则回退为 DRAFT。写入超时不自动重试：先读回远端评论（按正文精确匹配）或标签核对——一致按成功处理（不重复发送），不一致记录 UNCERTAIN 并提示人工到 GitHub 核对后再决定。
3. **本机审计。** 每次执行尝试写入 V23 `draft_executions`（随仓库登记与草稿级联删除）：确认时间、执行时间、执行的目标 / 依据 / 正文或标签快照、结果状态（SUCCESS / FAILED / UNCERTAIN）、外部链接与说明；payload 不保存任何凭据，响应与审计均校验不泄漏 Token。仅开放评论与标签两类操作；不提供任意请求、Shell 或自动合并 PR 工具。

API：`GET /api/development/drafts/write-option`、`POST /api/development/drafts/{id}/execution-previews`、`POST /api/development/drafts/{id}/executions`（body `previewId`/`confirmed`，未确认 400）、`GET /api/development/repositories/{id}/draft-executions`（最近 20 条）、`GET /api/development/draft-executions/{id}`。

# 取消与用量

运行中的排查可通过 `POST /api/runs/{id}/cancel` 取消。本机同源请求须带 `X-Triage-Run: 1`。返回保存后的执行记录；状态为 `CANCELLED`，保留证据、事件和已知模型用量，结论与失败信息为空。SSE 发送 `RUN_CANCELLED` 后完成连接。

重复取消不增加事件。若任务已经完成或失败，接口返回现有记录，不改写结果。未知记录返回 404，非法 ID 返回 400。取消、任务完成和结果写入在同一个执行锁内处理，迟到结果不能覆盖取消记录。

排队任务从队列移除；当前工具或模型任务收到中断请求，后续调用停止。不响应中断的代码仍可能占用工作线程，应用使用有界线程池限制资源。已经发给模型服务的请求可能继续执行并计费，取消本地等待不能保证服务方停止计算或退款。

模型记录增加以下可选字段，旧历史缺少这些字段时仍可读取：

| 字段 | 含义 |
|---|---|
| `calls` | 经过执行入口启动的轮次，包含尚未返回的等待 |
| `completedCalls` | 在本次执行内收到响应的轮次 |
| `usageReportedCalls` | 返回完整输入、输出和总 Token 计数的轮次 |
| `knownUsage` | 上述已知用量的累计值，缺失轮次不当作零 |
| `usage` | 所有启动轮次均返回完整用量时的总计，缺失、超时或取消等待时为空 |

开始新一轮不会清空先前的已知用量。用量与模型响应在同一执行锁内记录；取消后的迟到响应不会追加用量。数值来自模型接口，不包含未知轮次，费用以服务方账单为准。

取消不会更改模型配置或删除历史。服务重启只将未结束的 `QUEUED` 和 `RUNNING` 记录标记为中断，不改写已经取消的记录。

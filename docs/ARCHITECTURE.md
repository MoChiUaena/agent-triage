# 架构

项目采用 Spring Boot 单体，前端为原生 HTML / JavaScript，数据库通过 JDBC 访问。

## 请求流程

`RunController` 校验请求后，由 `RunService` 保存 QUEUED 记录并提交异步任务。任务依次检索文档、读取指标、查询日志，交给 `DemoReasoner` 生成结论。`EvidenceValidator` 检查引用后，保存最终状态。

浏览器通过 SSE 获取进度。`RunEventController` 每 200ms 读取一次执行记录，发送尚未推送的事件。前端按事件序号去重，点击引用可以展开本次执行的证据。

当前工具顺序和结论由固定规则决定。后续接入 Spring AI 时，会替换这部分逻辑，继续使用现有工具、状态管理和存储。

## 代码结构

| 包 / 文件 | 职责 |
|---|---|
| `domain/TriageModel` | 执行记录、事件、证据和结论的数据结构 |
| `tools/ToolContext` | 保存本次执行的服务、场景和时间窗口 |
| `tools/*Tool` | 文档、指标和日志查询 |
| `execution/RunService` | 异步调度、超时、失败处理与重启恢复 |
| `execution/EvidenceValidator` | 校验引用是否来自本次执行 |
| `store/RunRepository` | 保存和查询执行快照 |
| `api/RunEventController` | SSE 推送与事件重放 |
| `static/app.js` | 提问、进度、结论和历史记录页面 |

## 执行与超时

正常状态流为 `QUEUED → RUNNING → SUCCEEDED / INSUFFICIENT_EVIDENCE / FAILED`。队列满或排队超时也会从 QUEUED 进入 FAILED。

每个执行只有一个协调任务负责写状态。工具任务只返回数据，不写数据库。工具超时后，协调任务通过 `Future.cancel(true)` 请求中断并保存失败状态，因此迟到的工具返回值不会覆盖结果。

协调任务和工具任务各使用一个有界线程池，分别配置 4 个线程和 16 个等待位。提交队列已满时返回 HTTP 429。不响应中断的工具仍可能占用线程，但不会无限创建新线程。

默认每次执行最多调用 3 次工具，单次等待 2s，整体时限 10s。整体计时包含排队时间，使用单调时钟，在出队、调用工具和生成结论时检查。实际等待时间取单次工具时限与剩余总时限的较小值。数据库 I/O 和 JVM 调度不受这一取消机制控制。

SSE 最多同时接受 64 个连接，执行结束、连接异常或达到 25s 时限后释放连接。浏览器断开不会取消执行，记录仍保存在数据库中。

## 文档检索

语料目前只有三个短文档，使用关键词匹配，文档 ID 固定。这样不需要额外部署向量索引，也便于核对检索结果。

关键词匹配可能漏掉同义表述。例如在超时场景下询问“查看健康状态”，只会命中正常状态文档。此时指标和日志仍会返回，但缺少超时规则，结果为证据不足。后续是否引入语义检索取决于案例覆盖情况。

## 执行记录

H2 和 PostgreSQL 共用 `RunRepository` 与 Flyway 迁移。默认使用 H2 文件库，方便本地启动；PostgreSQL 兼容性由独立 CI 作业验证。

一次执行保存为一行 JSON 快照，包含状态、事件和证据。每次更新通过同一条 SQL 写入，避免状态与事件分开保存时出现不一致。SSE 直接读取快照，因此即使浏览器在执行完成后才订阅，也能收到完整事件。

这个实现会重复写入 JSON，历史列表也需要先读取快照再提取摘要。当前每次执行的工具调用数和返回量都有上限，暂时接受这部分开销。记录量增大后可拆分事件表，并改为只查询列表所需字段。

## 重启处理

启动时，将未完成记录标记为 `FAILED / SERVER_RESTARTED`，保留已有事件和证据，不自动重跑。

这套恢复逻辑只适用于单实例。多实例需要记录任务归属或引入租约，否则一个实例启动时可能误判另一个实例正在执行的任务。

## 引用校验

每条观察和原因都必须引用本次工具返回的证据，引用不能为空，证据 ID 不能重复。

ID 校验只能确认引用存在，无法判断文字结论是否被证据支持。当前结论由固定模板生成；模型接入后，这部分需要单独评测。

## 依赖版本

使用 Java 21、Spring Boot 3.5.16 和 Maven 3.9.11。POM 已固定 Spring AI 1.1.8 BOM，暂未引入模型运行时依赖。[该版本的官方文档](https://github.com/spring-projects/spring-ai/blob/v1.1.8/spring-ai-docs/src/main/antora/modules/ROOT/pages/getting-started.adoc)说明其支持 Spring Boot 3.4.x 和 3.5.x。

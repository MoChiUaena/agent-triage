# 开发计划

v0.1 聚焦订单查询变慢这一场景，通过日志、指标和排障文档定位可能的故障路径。排查过程只读，不执行修复操作。

## 已完成

- 正常与下游超时两种演示场景。
- 文档检索、指标读取和错误日志查询三个工具。
- 网页提问、SSE 进度、证据引用和历史记录。
- 调用次数限制、超时处理和重启恢复。
- H2 / PostgreSQL 存储，Windows / Linux CI。
- 独立订单与库存样例服务、跨进程 HTTP 超时、Micrometer 与 JSON 错误日志、LIVE 观测工具。

默认使用固定规则的演示模式，也可配置模型模式。测试结果见[测试说明](VALIDATION.md)。

## v0.6 计划

- [ ] 把 SQL 执行失败作为独立判断：同时核对查询失败计数、同窗口错误事件和排障规则，只报告失败阶段，不推断锁等待或数据库内部根因。
- [ ] 让固定规则和模型模式使用同一证据门槛；补充本地模型协议回归，保留旧记录的读取方式。
- [ ] 在独立数据库样例和公开 Petclinic 中验证正常查询、SQL 失败、连接获取超时及恢复，确认三种阶段不会混判。
- [ ] 为本机历史增加可配置的留存与清理入口，默认不自动删除，升级后旧记录仍可读取。

多用户鉴权、多实例协调和更多故障类型另列后续阶段；v0.6 不将单次 SQL 失败写成完整根因。

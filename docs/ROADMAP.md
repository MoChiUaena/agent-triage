# 开发计划

v0.1 聚焦订单查询变慢这一场景，通过日志、指标和排障文档定位可能的故障路径。排查过程只读，不执行修复操作。

## 已完成

- 正常与下游超时两种演示场景。
- 文档检索、指标读取和错误日志查询三个工具。
- 网页提问、SSE 进度、证据引用和历史记录。
- 调用次数限制、超时处理和重启恢复。
- H2 / PostgreSQL 存储，Windows / Linux CI。
- 独立订单与库存样例服务、跨进程 HTTP 超时、Micrometer 与 JSON 错误日志、LIVE 观测工具。

默认使用固定规则的演示模式，也可配置模型模式。测试结果见[测试说明](VALIDATION.md)。

## 下一阶段：入站请求与执行阶段失败

没有 HTTP 下游的 Petclinic 仍需填写占位 origin；普通请求异常只能显示证据不足。先解决这两处真实接入缺口，再评估其他客户端和故障类型。

- [x] 提供 `HTTP_REQUESTS` / `HTTP_REQUESTS_V4`，无下游项目不再填写占位配置；窗口、接口与历史区分未采集和测得的零值，固定规则／模型不生成下游成功判断。[接入说明](INBOUND_HTTP.md) / [验收记录](validation/2026-10-02-inbound-http.md)
- [x] 增加入站 V4 可选请求失败分类与执行阶段判断，固定规则／模型共用同窗口计数、响应、事件和规则门槛；单纯 5xx、异步超时／错误、已处理异常或缺少证据不生成成功判断。[配置](REQUEST_EXECUTION.md) / [验收记录](validation/2026-10-02-request-execution.md)
- [x] 在固定 Petclinic／REST 核对原接口、请求异常、正常恢复、单纯 5xx、下游超时、Callable、Servlet 超时、迟到结果及 SQL/HTTP 双侧差异；保留缺少场景和断言错误的失败记录。[混合对照](validation/2026-10-02-mixed-public-diagnostics.md)
- [ ] 验收后整理 v0.11 预览交付和旧历史升级检查，纳入容量与资源释放修复，保留 v0.10.0 原附件。

小时／天级稳定性、原生内存、其他 HTTP 客户端、多数据源、非回环接入和多实例协调继续单独评估，不与新的请求失败判断混为一项。

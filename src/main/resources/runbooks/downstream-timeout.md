# 下游读取超时排障

文档 ID：DOC-DOWNSTREAM-TIMEOUT#v1。适用服务：order-service。本文用于合成演示。

订单查询同步调用 inventory-service。当订单接口 p95 和库存调用 p95 同时升高，且日志出现 SocketTimeoutException / Read timed out，优先验证下游调用超时路径。

演示的读取超时配置为 2000ms。只有指标与错误日志共同支持时，才提出“库存下游超时可能拖慢订单查询”的判断。

下一步：按同一时间窗口核对库存服务延迟和错误率；用 traceId 对照调用链；核实客户端读取超时配置。

这些证据无法区分下游资源饱和、网络延迟或客户端连接池等待，不能直接断言最终根因，更不能仅增大超时就声称修复。
